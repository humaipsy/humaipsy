What it does

Built for the experiment, not the demo.

Every part of Humai exists to serve a trial: run it, time it, record it, and hand back data a statistics package can read.

01

Counterbalanced trial design

A within-subject design, condition order counterbalanced by participant ID, with a researcher-set number of trials per condition.

02

Triple-recorded output

Every trial lands in a per-experiment CSV, a mirrored JSONL audit ledger with SHA-256 run hashes, and a full SQLite chat transcript.

03

Local and offline-first

No telemetry, no account, no required network dependency beyond the provider host you point it at, e.g., Ollama. Air-gap mode blocks all outbound HTTP.

04

Read-only live dashboard

An optional local web view of the running experiment — loopback-only by default, gated by the same master-password vault as the desktop app.

05

Master-password vault

Argon2id-hashed lock on the application with throttled retry backoff.

06

Cross-platform releases

Native builds for Windows, Linux, and Apple Silicon macOS — no build step beyond cargo, no bundled runtime to install.

Two audiences, one instrument

Read from your own field.

Cognitive science, HCI & experimental psychology

A proper within-subject protocol

  • Counterbalanced condition ordering built into the trial engine
  • Participant ID, per-trial timing, and a free-text final answer captured on a fixed schema
  • CSV output designed to drop straight into R, Python, SPSS, or JASP
  • A named privacy/security document written for IRB review
AI & ML researchers

Reproducible model-behavior trials

  • Runs against a local model provider — Ollama is a great way to produce results
  • Per-turn timing capture, time-to-first-token and prompt/eval token counts
  • Air-gapped evaluation runs against a fully local model
Under the hood

A pure Rust backend, end to end.

The experiment engine, the desktop UI, and the local dashboard's axum server all compile from one Rust codebase into a single native binary — no separate backend process, no bundled runtime, no interpreter. That same codebase targets Windows, Linux, and macOS directly, so the same trial logic runs identically wherever a study is conducted, with no build step beyond cargo.
